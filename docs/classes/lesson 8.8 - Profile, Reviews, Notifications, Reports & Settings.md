## অংশ ১ — Prompt 32, 33: প্রোফাইল

### ডেটা কোথা থেকে?

| দেখাবো | সোর্স |
|---|---|
| নাম, ভেরিফাইড, আইনগত নাম, রেটিং | `GET /users/me` (auth store) |
| সক্রিয় বিজ্ঞাপন সংখ্যা | `GET /listings/my?status=active&limit=1` → `total` |
| বিক্রিত সংখ্যা | `GET /listings/my?status=sold&limit=1` → `total` |

`limit=1` দিয়ে শুধু `total` নেওয়া — একটা ছোট্ট কিন্তু কাজের ট্রিক (পুরো লিস্ট লোড করতে হয় না)।

### প্রোফাইল ছবি কেন নেই?

ব্যাকএন্ডের User মডেলে avatar ফিল্ড নেই। তাই নামের প্রথম অক্ষর + নাম থেকে বানানো রং দিয়ে অ্যাভাটার। **শিক্ষণীয়:** প্রম্পট লেখার আগে ব্যাকএন্ড কী সাপোর্ট করে দেখে নিতে হয় — না হলে AI এমন ফিচার বানাবে যেটা সেভই হবে না।

### ডিসপ্লে নেম বনাম আইনগত নাম

- `displayName` — ইউজার নিজে বদলাতে পারে (১–৩০ অক্ষর, HTML স্ট্রিপ হয়)
- `verifiedName` — KYC অ্যাপ্রুভের সময় অ্যাডমিন NID দেখে সেট করে, ইউজার বদলাতে পারে না

বিশ্বাসের জন্য দুটোই দেখাই: "রাকিব ভাই (আইনগত নাম: MD RAKIB HASAN)"।

## অংশ ২ — Prompt 34, 35: রিভিউ

### ব্যাকএন্ডের রুল (বোর্ডে লিখুন)

`POST /reviews { listingId, rating, reviewText }` সফল হবে শুধু যদি:

1. বিজ্ঞাপনের `status === 'sold'`
2. `soldToBuyerId === আমি` (বিক্রেতা আমাকেই বেছে নিয়েছে)
3. এই বিজ্ঞাপন নিয়ে আমার আর বিক্রেতার চ্যাট রুম আছে
4. এই বিজ্ঞাপনের আগে কোনো রিভিউ নেই (একটা বিজ্ঞাপনে একটাই রিভিউ)
5. rating পূর্ণসংখ্যা ১–৫, reviewText আবশ্যক (≤৫০০)

**প্রশ্ন করুন:** "ফেক রিভিউ কি সম্ভব?" → না, কারণ চ্যাট + বিক্রেতার কনফার্মেশন দুটোই লাগে।

### কখন রিভিউ প্রম্পট দেখাবো?

চ্যাট রুমের ডেটাতেই আছে:

```ts
const canReview =
  room.buyerId === me.id &&
  room.listing?.status === 'sold' &&
  room.listing?.soldToBuyerId === me.id;
```

রিভিউ দেওয়ার পর `409 DUPLICATE_ENTRY` এড়াতে রিভিউ করা listingId গুলো AsyncStorage-এ মনে রাখুন।

### রেটিং কীভাবে আপডেট হয়?

ব্যাকএন্ড ট্রানজ্যাকশনের ভেতরে রিভিউ সেভ করে, তারপর aggregate দিয়ে বিক্রেতার `averageRating` ও `totalReviews` আবার হিসাব করে। ক্লায়েন্টে শুধু query invalidate করলেই নতুন রেটিং দেখা যাবে।

### রিভিউ লিস্টের ডেটা

```jsonc
{ "reviews": [ { "rating": 5, "reviewText": "...",
                 "reviewerId": { "id": "...", "displayName": "সাদিয়া", "isVerified": true },
                 "listingId": { "id": "...", "title": "MacBook Air M1", "images": [...] } } ],
  "total": 12, "page": 1, "totalPages": 1, "averageRating": 4.8 }
```

## অংশ ৩ — Prompt 36, 37, 38: নোটিফিকেশন

### গুরুত্বপূর্ণ বাস্তবতা (ক্লাসে সৎভাবে বলুন)

ব্যাকএন্ড পুশ টোকেন **সেভ করে** (`PUT /users/me { fcmToken }`), কিন্তু এখনো **পুশ পাঠায় না** (কোডে TODO)। তাই আমরা:

| ইভেন্ট | কীভাবে জানবো | কী দেখাবো |
|---|---|---|
| নতুন চ্যাট মেসেজ | সকেট `new_message` | অ্যাপ খোলা → ইন-অ্যাপ ব্যানার; ব্যাকগ্রাউন্ডে → লোকাল নোটিফিকেশন |
| KYC অ্যাপ্রুভ/রিজেক্ট | অ্যাপ ফোরগ্রাউন্ডে `GET /kyc/status` | লোকাল নোটিফিকেশন / ব্যানার |
| বিজ্ঞাপন অ্যাপ্রুভ/রিজেক্ট/মেয়াদ | `GET /listings/my` আগের স্ন্যাপশটের সাথে তুলনা | লোকাল নোটিফিকেশন |

এভাবে ব্যাকএন্ড বদলানো ছাড়াই ইউজার জানতে পারে। ভবিষ্যতে ব্যাকএন্ড Expo Push API দিয়ে পাঠালে, টোকেন আগে থেকেই রেজিস্টার্ড থাকবে।

> ⚠️ ব্যাকগ্রাউন্ডে লোকাল নোটিফিকেশন শুধু তখনই কাজ করবে যখন সকেট এখনো কানেক্টেড — অ্যাপ পুরোপুরি বন্ধ থাকলে আসল পুশ লাগে। এটা স্টুডেন্টদের ফাইনাল প্রজেক্টের জন্য ভালো "এক্সটেনশন টাস্ক"।

### পুশ টোকেন

```ts
const { status } = await Notifications.requestPermissionsAsync();
if (status === 'granted' && Device.isDevice) {
  const token = (await Notifications.getExpoPushTokenAsync({ projectId })).data;
  await api.put('/users/me', { fcmToken: token });
}
```

- Android-এ Expo Go-তে রিমোট পুশ কাজ করে না → **development build** লাগে (Lesson 8.9)।
- পারমিশন চাওয়ার আগে ছোট একটা ব্যাখ্যা স্ক্রিন — iOS-এ একবার "না" বললে আবার জিজ্ঞেস করা যায় না।

### নোটিফিকেশন ট্যাপ → সঠিক স্ক্রিন

```ts
Notifications.addNotificationResponseReceivedListener((res) => {
  const data = res.notification.request.content.data;
  if (data.type === 'chat') router.push(`/chat/${data.roomId}`);
});
```

অ্যাপ বন্ধ অবস্থায় ট্যাপ করলে `getLastNotificationResponseAsync()` দিয়ে ধরতে হয়।

### ইন-অ্যাপ ব্যানার (Prompt 37)

Zustand-এ একটা কিউ: `showNotification({...})` → রুট লেআউটে একটা ব্যানার কম্পোনেন্ট কিউ থেকে একটা একটা করে দেখায়, ৪ সেকেন্ডে চলে যায়।

### প্রেফারেন্স (Prompt 38)

ব্যাকএন্ডে কোনো প্রেফারেন্স API নেই → AsyncStorage। `shouldNotify(type)` একটা জায়গায় রাখলে সব নোটিফিকেশন কোড সেটা ব্যবহার করবে।

## অংশ ৪ — Prompt 39, 40: রিপোর্ট

### ভ্যালু ম্যাপিং (সবচেয়ে কমন বাগ)

| UI (বাংলা) | API value |
|---|---|
| প্রতারণা / স্ক্যাম | `scam` |
| হয়রানি | `harassment` |
| ভুল দাম/বর্ণনা | `misrepresentation` |
| অনুপযুক্ত কন্টেন্ট | `inappropriate` |
| অন্যান্য | `other` |

- `targetType` হুবহু `'Listing'` বা `'User'` (বড় হাতের প্রথম অক্ষর)।
- `description` **আবশ্যক** — খালি পাঠালে `VALIDATION_FAILED`।
- একই জিনিস দুবার রিপোর্ট → `409 DUPLICATE_REPORT`; নিজেকে/নিজের বিজ্ঞাপন রিপোর্ট করা যায় না।

অ্যাডমিন ওয়েবের `/admin/reports` থেকে resolve/dismiss করে; অ্যাপের "আমার রিপোর্ট"-এ স্ট্যাটাস ও `resolution` দেখা যায়। লাইভ ডেমোতে দেখান।

## অংশ ৫ — Prompt 41, 42, 43: সেটিংস ও অ্যাকাউন্ট ডিলিট

### থিম মোড

`ui.store`-এ `themeMode: 'system' | 'light' | 'dark'` (persisted); `useTheme()` এটা আর `useColorScheme()` মিলিয়ে প্যালেট দেয়।

### অ্যাকাউন্ট ডিলিট — ব্যাকএন্ড কী করে?

`DELETE /users/me`:
1. `status = inactive`, `deletionRequestedAt = now`
2. সব সক্রিয়/পেন্ডিং বিজ্ঞাপন আর্কাইভ
3. `tokenVersion + 1` → **সব ডিভাইসের সব টোকেন বাতিল**
4. ৩০ দিন পর শিডিউলার নাম/ফোন/KYC ডেটা মুছে দেয়; এর মধ্যে আবার OTP দিয়ে লগইন করলে অনুরোধ বাতিল

তাই ডিলিটের পর `/auth/logout` কল করা যাবে না (টোকেন আগেই বাতিল → 401) — শুধু লোকাল ডেটা মুছে welcome স্ক্রিনে পাঠাতে হবে।

### UX: "DELETE" টাইপ করে কনফার্ম

ঝুঁকিপূর্ণ অ্যাকশনে দুই ধাপ — পরিণাম দেখাও, তারপর টাইপ করে কনফার্ম। ভুলে চাপ লেগে অ্যাকাউন্ট যাবে না।

### Google Play-এর নিয়ম

অ্যাকাউন্ট খোলা যায় এমন অ্যাপে **অ্যাপের ভেতর থেকে অ্যাকাউন্ট ডিলিট** অপশন থাকা বাধ্যতামূলক — না থাকলে স্টোর রিজেক্ট করে।

## 🧪 এন্ড-টু-এন্ড ডেমো: "বিক্রি → রিভিউ"

1. ফোন A (বিক্রেতা) বিজ্ঞাপন দিয়েছে, ফোন B (ক্রেতা) চ্যাট করেছে।
2. A: আমার বিজ্ঞাপন → "বিক্রি হয়েছে" → B-কে বেছে নেয়।
3. B: চ্যাট খোলে → "আপনি পণ্যটি কিনেছেন! রিভিউ দিন" → ৫⭐ + লেখা → জমা।
4. A-এর প্রোফাইলে রেটিং ও রিভিউ সংখ্যা আপডেট।
5. B আবার রিভিউ দিতে গেলে → "আগেই রিভিউ দিয়েছেন"।
6. B, A-কে রিপোর্ট করে → অ্যাডমিন resolve → B-এর "আমার রিপোর্ট"-এ স্ট্যাটাস বদলায়।

## 🛠 ট্রাবলশুটিং

| সমস্যা | কারণ | সমাধান |
|---|---|---|
| রিভিউতে `403 Only the buyer can review` | বিক্রেতা অন্য কাউকে বেছে নিয়েছে | `soldToBuyerId` চেক করে প্রম্পট দেখান |
| রিপোর্টে `VALIDATION_FAILED` | reason বাংলায় গেছে / description খালি | value ম্যাপিং, description আবশ্যক |
| পুশ টোকেন আসে না | সিমুলেটর / Expo Go Android / projectId নেই | আসল ডিভাইস + dev build + `eas init` |
| ডিলিটের পর 401 লুপ | ডিলিটের পর logout API কল | localLogout ব্যবহার |
| নোটিফিকেশন ট্যাপে কিছু হয় না | cold start হ্যান্ডেল নেই | `getLastNotificationResponseAsync` |

## 📝 হোমওয়ার্ক

1. প্রোফাইলে "রেটিং ডিস্ট্রিবিউশন" বার চার্ট (৫★ … ১★) বানান।
2. সেটিংসে "ক্যাশ পরিষ্কার করুন" অপশন — TanStack Query ক্যাশ + expo-image ক্যাশ।
3. **চ্যালেঞ্জ (ঐচ্ছিক, ব্যাকএন্ড):** নতুন মেসেজে Expo Push API দিয়ে পুশ পাঠানোর একটা ডিজাইন ডক লিখুন — কোন ফাইলে, কোন ইভেন্টে, invalid টোকেন কীভাবে মুছবেন।

## ❓ কুইজ

1. কে রিভিউ দিতে পারে? → **যাকে বিক্রেতা "বিক্রি হয়েছে"-তে বেছে নিয়েছে এবং যার চ্যাট আছে**
