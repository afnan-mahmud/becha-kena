## অংশ ১ — Prompt 44: চারটি স্টেট

প্রতিটি ডেটা-স্ক্রিনের জন্য স্টুডেন্টদের এই প্রশ্ন করতে শেখান:

| স্টেট | প্রশ্ন | UI |
|---|---|---|
| Loading | ডেটা আসছে? | স্কেলিটন (স্পিনারের চেয়ে ভালো — লেআউট লাফায় না) |
| Empty | ডেটা এসেছে কিন্তু খালি? | ইমোজি/আইকন + বাক্য + অ্যাকশন বাটন |
| Error | রিকোয়েস্ট ফেল? | মেসেজ + "আবার চেষ্টা করুন" |
| Offline | ইন্টারনেট নেই? | উপরে ব্যানার + ক্যাশড ডেটা দেখানো |

```tsx
if (query.isLoading) return <SkeletonList />;
if (query.isError) return <EmptyState variant="error" onAction={query.refetch} />;
if (!items.length) return <EmptyState variant="noListings" />;
return <FlatList ... />;
```

অডিট এক্সারসাইজ (লাইভ): এয়ারপ্লেন মোড চালু করে প্রতিটা স্ক্রিন খুলুন — কোথায় সাদা স্ক্রিন বা চিরস্থায়ী স্পিনার আসছে?

## অংশ ২ — Prompt 45: অ্যানিমেশন

- **উদ্দেশ্যপূর্ণ অ্যানিমেশন:** ফিডব্যাক (বাটন প্রেস), কন্টিনিউটি (স্ক্রিন ট্রানজিশন), আনন্দ (সাকসেস চেকমার্ক)। সাজসজ্জার জন্য অ্যানিমেশন নয়।
- Reanimated layout animation: `entering={FadeInDown.delay(index * 40)}` — শুধু প্রথম ১০টা আইটেমে, না হলে লম্বা লিস্ট স্লো।
- `useReducedMotion()` — যারা Reduce Motion চালু রেখেছেন তাদের জন্য বন্ধ।
- হ্যাপটিক ছোট্ট কিন্তু "প্রিমিয়াম" অনুভূতি দেয়: প্রাইমারি অ্যাকশনে `Haptics.impactAsync(Light)`।

## অংশ ৩ — Prompt 46: অফলাইন ও এরর

### NetInfo + TanStack Query

```ts
onlineManager.setEventListener((setOnline) =>
  NetInfo.addEventListener((s) => setOnline(!!s.isConnected && s.isInternetReachable !== false))
);
focusManager.setEventListener((handleFocus) => {
  const sub = AppState.addEventListener('change', (st) => handleFocus(st === 'active'));
  return () => sub.remove();
});
```

ফলাফল: অফলাইনে query থেমে থাকে, অনলাইন হলে অটো রিফেচ; অ্যাপে ফিরে এলে ডেটা ফ্রেশ।

### এরর মেসেজের নীতি

- টেকনিক্যাল টেক্সট ("Request failed with status code 500") কখনো না।
- ব্যাকএন্ডের `error` মেসেজ ভালো হলে সেটাই, না হলে status/code অনুযায়ী বাংলা মেসেজ।
- সবসময় একটা পরবর্তী পদক্ষেপ দিন ("আবার চেষ্টা করুন", "লগইন করুন")।

### Error Boundary

Expo Router-এ রুট লেআউট থেকে `export function ErrorBoundary({ error, retry })` এক্সপোর্ট করলেই রেন্ডার ক্র্যাশ ধরা যায় — সাদা স্ক্রিনের বদলে "কিছু একটা সমস্যা হয়েছে"।

## অংশ ৪ — Prompt 47: টাইপস = ব্যাকএন্ডের সাথে চুক্তি

কেন? ব্যাকএন্ড `sellerId`-কে কখনো string আর কখনো object দেয়:

```ts
sellerId: string | SellerSummary;
const seller = typeof listing.sellerId === 'object' ? listing.sellerId : null;
```

টাইপে এটা লিখে রাখলে TypeScript নিজেই ভুল জায়গা ধরিয়ে দেয়। লক্ষ্য: `npx tsc --noEmit` → **০ এরর**, কোডে কোনো `any` নেই।

**ক্লাস আলোচনা:** এই কোর্সের শুরুতে প্রম্পটে `id` ব্যবহার করা হয়েছিল কিন্তু ব্যাকএন্ড আগে `_id` দিত — ঠিক এই ধরনের অমিল টাইপ আর API কন্ট্র্যাক্ট ডক থাকলে শুরুতেই ধরা পড়ে।

## অংশ ৫ — Prompt 48: E2E টেস্টিং (লাইভ)

দুটো ফোন + ওয়েব অ্যাডমিন নিয়ে পুরো জার্নি চালান:

```
নতুন ইউজার → অনবোর্ডিং → OTP → KYC সাবমিট → (অ্যাডমিন অ্যাপ্রুভ) → ভেরিফাইড
→ বিজ্ঞাপন পোস্ট → (অ্যাডমিন অ্যাপ্রুভ) → অন্য ফোনে সার্চে পাওয়া
→ চ্যাট → বিক্রি হয়েছে → রিভিউ → রিপোর্ট → (অ্যাডমিন resolve)
→ অ্যাকাউন্ট ডিলিট → আবার লগইন (রিস্টোর)
```

প্রম্পটের চেকলিস্ট `mobile-app/TESTING.md`-এ লিখে রাখুন — প্রতিটি রিলিজের আগে আবার চালানো হবে। এটাই **রিগ্রেশন টেস্টিং**।

এজ কেস ভুলবেন না: ছোট স্ক্রিন (iPhone SE), বড় ফন্ট সেটিং, লম্বা বাংলা টেক্সট, Android ব্যাক বাটন, ডার্ক মোড, স্লো নেটওয়ার্ক (ডেভ টুলে নেটওয়ার্ক থ্রটলিং)।

## অংশ ৭ — Prompt 50, 51, 52: প্রোডাকশন ও রিলিজ

### কনফিগ

| কী | মান |
|---|---|
| bundle id / package | `com.bechakena.app` (একবার পাবলিশ হলে আর বদলানো যায় না!) |
| scheme | `bechakena` → ডিপ লিংক `bechakena://listing/123` |
| splash / icon | সবুজ `#00704A` + সাদা লোগো |
| পারমিশন টেক্সট | ক্যামেরা (সেলফি), ফটো (বিজ্ঞাপন), লোকেশন (কাছাকাছি), নোটিফিকেশন |

### এনভায়রনমেন্ট

```
development → http://<LAN-IP>:5000         (লোকাল ব্যাকএন্ড)
preview     → https://staging-api.…        (টেস্টারদের জন্য APK)
production  → https://api.bechakena.com    (স্টোর বিল্ড)
```

- রিলিজ বিল্ডে Android **HTTP ব্লক করে** — প্রোডাকশনে HTTPS বাধ্যতামূলক।
- সকেটের জন্য রিভার্স প্রক্সিতে (Nginx) WebSocket upgrade হেডার লাগে, না হলে চ্যাট কাজ করবে না।
- `EXPO_PUBLIC_*` অ্যাপে এমবেড হয় — কোনো সিক্রেট না।

### EAS কমান্ড

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest build --profile development --platform android   # ডেভ ক্লায়েন্ট (পুশ, নেটিভ মডিউল টেস্ট)
npx eas-cli@latest build --profile preview --platform android       # APK → টেস্টারদের দিন
npx eas-cli@latest build --profile production --platform all        # স্টোর বিল্ড
npx eas-cli@latest submit --profile production --platform android
npx eas-cli@latest update --channel production --message "fix: ..." # OTA হটফিক্স
```

**Expo Go বনাম Development Build:** Expo Go-তে শুধু Expo-র বান্ডেল করা নেটিভ মডিউল থাকে; Android-এ রিমোট পুশ নেই। আসল টেস্টিং ও প্রোডাকশনের জন্য development build।

**OTA আপডেট কখন চলবে, কখন না:** শুধু JS/অ্যাসেট পরিবর্তন → `eas update`; নতুন নেটিভ প্যাকেজ বা পারমিশন → নতুন বিল্ড + স্টোর রিভিউ।

### স্টোর লিস্টিং চেকলিস্ট

- নাম: "বেচা-কেনা — Verified Marketplace"
- বাংলা + ইংরেজি বিবরণ, স্ক্রিনশট (ফোনের সাইজ অনুযায়ী)

## 🎓 কোর্স র‍্যাপ-আপ

এই ৬টি ক্লাসে আমরা একটা আসল প্রোডাকশন অ্যাপ বানালাম যেটা —

- একই ব্যাকএন্ড ওয়েবের সাথে শেয়ার করে (cookie বনাম Bearer token)
- NID ভেরিফিকেশন দিয়ে বিশ্বাস তৈরি করে
- রিয়েল-টাইম চ্যাট, রিভিউ ও রিপোর্ট দিয়ে নিরাপদ marketplace চালায়
- বাংলা-প্রথম ডিজাইনে বাংলাদেশের ইউজারদের জন্য বানানো

সবচেয়ে বড় শিক্ষা: **AI দিয়ে কোড লেখা দ্রুত, কিন্তু সঠিক প্রম্পট, ব্যাকএন্ড কন্ট্র্যাক্ট বোঝা আর প্রতিটি আউটপুট টেস্ট করা — এটাই একজন ভালো ডেভেলপারের কাজ।**
