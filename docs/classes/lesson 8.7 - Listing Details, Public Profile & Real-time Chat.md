# Lesson 8.7 — বিজ্ঞাপনের ডিটেইল, পাবলিক প্রোফাইল ও রিয়েল-টাইম চ্যাট

> **কভার করা প্রম্পট:** Prompt 24 – 31 (Phase 6 + Phase 7)
> **সময়:** ~৩ ঘণ্টা
> **ক্লাস শেষে যা থাকবে:** ইমেজ ক্যারোসেল ও জুমসহ বিজ্ঞাপনের ডিটেইল পেজ, বিক্রেতার পাবলিক প্রোফাইল, "চ্যাট করুন" থেকে রুম তৈরি, Socket.io দিয়ে রিয়েল-টাইম মেসেজ, টাইপিং ইন্ডিকেটর, রিড টিক ও আনরিড ব্যাজ।

## 🎯 শেখার লক্ষ্য

1. ডাইনামিক রাউট (`listing/[id]`) ও প্যারামস পড়া।
2. **কন্ডিশনাল UI** — ভিউয়ার কে (গেস্ট / আনভেরিফাইড / ভেরিফাইড / নিজের বিজ্ঞাপন) তার উপর ভিত্তি করে বাটন।
3. **Gesture + Reanimated** দিয়ে পিঞ্চ-টু-জুম।
4. **WebSocket** বনাম HTTP — কেন চ্যাটে সকেট লাগে।
5. Socket.io-এর **namespace, room, event, ack**।
6. টোকেন দিয়ে সকেট অথেনটিকেশন ও রিকানেক্ট।
7. রিয়েল-টাইম স্টেট (Zustand) — মেসেজ ডি-ডুপ্লিকেশন, আনরিড কাউন্ট।
8. Inverted FlatList দিয়ে চ্যাট UI ও কিবোর্ড হ্যান্ডলিং।

## অংশ ১ — Prompt 24: বিজ্ঞাপনের ডিটেইল

### কনসেপ্ট: একই API, ভিন্ন ভিউয়ার, ভিন্ন ডেটা

`GET /listings/:id` **optional auth** — টোকেন থাকলে ব্যাকএন্ড জানে কে দেখছে:

| ভিউয়ার | `sellerId.phoneNumber` | পেন্ডিং বিজ্ঞাপন |
|---|---|---|
| গেস্ট | `null` | 404 |
| আনভেরিফাইড | `null` | 404 |
| ভেরিফাইড (hidePhoneNumber false) | `"+8801712345678"` | 404 |
| নিজের বিজ্ঞাপন / অ্যাডমিন | নম্বর | দেখা যায় |

এটাই **"নিরাপত্তা সার্ভারে, সুবিধা ক্লায়েন্টে"** নীতি — অ্যাপে বাটন লুকালেই যথেষ্ট না, সার্ভার নিজেই ডেটা দেয় না।

### বটম বারের লজিক

```tsx
if (isOwner) return <OwnerActions />;            // এডিট, আমার বিজ্ঞাপন
if (listing.status !== 'active') return null;     // বিক্রিত/আর্কাইভড
return (
  <>
    <Button title="💬 চ্যাট করুন" onPress={startChat} />
    {listing.hidePhoneNumber
      ? <Text>🔒 বিক্রেতা শুধু চ্যাটে যোগাযোগ করতে চান</Text>
      : <Button title="📞 কল করুন" onPress={call} />}
  </>
);
```

### চ্যাট শুরু

```ts
const startChat = async () => {
  if (!guard()) return;                                 // useRequireVerified
  const room = await createRoom(listing.id);           // POST /chat/rooms { listingId }
  router.push(`/chat/${room.id}`);
};
```

ব্যাকএন্ড `upsert` করে — একই ক্রেতা-বিক্রেতা-বিজ্ঞাপনের জন্য একটাই রুম, যতবারই চাপুক।

## অংশ ৩ — Prompt 26: পাবলিক প্রোফাইল

তিনটা API একসাথে (প্যারালাল query):


## অংশ ৪ — থিওরি: WebSocket ও Socket.io

### কেন HTTP যথেষ্ট না?

HTTP-তে ক্লায়েন্ট জিজ্ঞেস না করলে সার্ভার কিছু পাঠাতে পারে না। চ্যাটে প্রতি ২ সেকেন্ডে "নতুন মেসেজ আছে?" জিজ্ঞেস করা (polling) ব্যাটারি ও ডেটা নষ্ট করে। **WebSocket** একটা খোলা দুই-মুখী সংযোগ — সার্ভার যখন খুশি পাঠাতে পারে।

### আমাদের সকেট আর্কিটেকচার

```
            namespace: /chat   (শুধু ভেরিফাইড ইউজার)
 ┌──────────────────────────────────────────────────────┐
 │ room "user:<buyerId>"   ← কানেক্ট করলেই অটো জয়েন    │
 │ room "user:<sellerId>"                                │
 │ room "<chatRoomId>"     ← কনভারসেশন খুললে join_room  │
 └──────────────────────────────────────────────────────┘

send_message ─▶ সার্ভার DB-তে সেভ (লিংক/ফোন নম্বর স্যানিটাইজ)
             ─▶ new_message → chatRoom + দুজনের personal room
                (Socket.io ডুপ্লিকেট বাদ দেয় — প্রতিটি সকেট একবারই পায়)
```

এই কারণেই চ্যাট লিস্টে থাকা অবস্থায়ও নতুন মেসেজ আসে আর আনরিড ব্যাজ বাড়ে।

### ইভেন্ট টেবিল (বোর্ডে লিখুন)

| আমরা পাঠাই | সার্ভার পাঠায় |
|---|---|
| `join_room {roomId}` | `room_joined` |
| `leave_room {roomId}` | |
| `send_message {roomId, messageText}` + ack | `new_message` (Message) |
| `typing {roomId}` | `user_typing {roomId, userId}` |
| `mark_read {roomId}` | `messages_read {roomId, readBy}` |
| | `message_warning {warnings}`, `chat_error` |

⚠️ অনলাইন/অফলাইন (presence) ইভেন্ট ব্যাকএন্ডে **নেই** — UI-তে "অনলাইন" দেখাবো না।

### Ack (acknowledgement) কী?

```ts
socket.emit('send_message', { roomId, messageText }, (res) => {
  if (!res.success) showError(res.error);   // সার্ভার কনফার্ম করলো
});
```

HTTP রেসপন্সের মতো — পাঠানো মেসেজ সফল হলো কিনা জানা যায়।

## অংশ ৫ — Prompt 27: সকেট সিঙ্গেলটন

### কেন সিঙ্গেলটন?

প্রতি স্ক্রিনে নতুন কানেকশন খুললে একই ইউজারের ৫টা সকেট — ডুপ্লিকেট মেসেজ, ব্যাটারি নষ্ট। পুরো অ্যাপে **একটা** কানেকশন।

### টোকেন দিয়ে অথ ও রিকানেক্ট

```ts
socket = io(`${SOCKET_URL}/chat`, { auth: { token }, transports: ['websocket'] });

socket.on('connect_error', async (err) => {
  if (err.message.includes('Token') || err.message.includes('Authentication failed')) {
    const ok = await refreshAccessToken();          // api.ts-এর একই ফাংশন
    if (ok) { socket.auth = { token: await getAccessToken() }; socket.connect(); }
    else authStore.localLogout();
  }
});
```

Access token ১৫ মিনিটে শেষ হয় — রিকানেক্টের সময় **সর্বশেষ** টোকেন দিতে হবে, না হলে লুপে আটকে যাবে।

`SOCKET_URL`-এ `/api/v1` থাকবে না — শুধু `http://192.168.0.105:5000`।

## অংশ ৬ — Prompt 28: চ্যাট স্টোর

মূল চ্যালেঞ্জগুলো:

1. **ডি-ডুপ্লিকেশন:** একই মেসেজ ack আর `new_message` দুইভাবে আসতে পারে → `id` দিয়ে চেক।
2. **ক্রম:** API মেসেজ দেয় **নতুন থেকে পুরনো**; UI-তে আমরা পুরনো → নতুন রাখি (অথবা inverted FlatList-এ সরাসরি)।
3. **আনরিড:** মেসেজ আমার না **এবং** সেই রুম খোলা না → `unreadCount + 1`।
4. **অজানা রুম:** নতুন রুমের প্রথম মেসেজ এলে `fetchRooms()`।

```ts
addMessage: (m) => set((s) => {
  const list = s.messagesByRoom[m.roomId] ?? [];
  if (list.some((x) => x.id === m.id)) return s;
  ...
}),
```

## অংশ ৭ — Prompt 29–31: চ্যাট UI

### "অন্য মানুষ" কে?

```ts
const other = room.sellerId === me.id ? room.buyer : room.seller;
```

### Inverted FlatList

`inverted` দিলে লিস্ট নিচ থেকে শুরু হয় — চ্যাটের জন্য পারফেক্ট। ডেটা newest-first দিলেই হয় (API যেভাবে দেয়)। "পুরনো মেসেজ লোড" = `onEndReached` (inverted-এ উপরে)।

### রিড রিসিপ্ট

```
আমি পাঠালাম  → ✓  (readStatus false)
সে চ্যাট খুললো → mark_read → সার্ভার messages_read {readBy: সে}
               → আমার মেসেজগুলো readStatus true → ✓✓ (হলুদ)
```

### সার্ভারের স্যানিটাইজেশন (লাইভ দেখান)

`"আমার নম্বর 01712345678, www.fakesite.com দেখুন"` পাঠান → আসবে `"আমার নম্বর ***** *****, [link removed] দেখুন"` + সতর্কবার্তা। আর `"bkash advance দিন"` লিখলে "Caution: Never send advance payment." — এটাই প্রতারণা ঠেকানোর ফিচার।

### কিবোর্ড

`KeyboardAvoidingView` iOS-এ `behavior="padding"`, Android-এ সাধারণত `"height"` বা কিছু না (`softwareKeyboardLayoutMode`)। হেডারের উচ্চতা `keyboardVerticalOffset`-এ দিন।

## 🧪 লাইভ ডেমো: দুই ফোনে চ্যাট

1. ফোন A (বিক্রেতা) — একটা সক্রিয় বিজ্ঞাপন আছে।
2. ফোন B (ক্রেতা) — বিজ্ঞাপন খুলে "চ্যাট করুন"।
3. B: "আসসালামু আলাইকুম, এখনো আছে?" → A-এর চ্যাট ট্যাবে ব্যাজ "১" (A রুম না খুললেও!)
4. A রুম খোলে → B-এর মেসেজে ✓✓
5. A টাইপ করছে → B দেখে "টাইপ করছে…"
6. B ফোন নম্বর পাঠানোর চেষ্টা → মাস্কড + সতর্কতা
7. Wi-Fi বন্ধ-চালু → অটো রিকানেক্ট

2. টাইপিং ইভেন্ট রিসিভ করার নাম কী? → **`user_typing`**
3. ack কী? → **emit-এর কলব্যাক — সার্ভার ফলাফল জানায়**
4. ফোন নম্বর কেন `null` আসতে পারে? → **ভিউয়ার ভেরিফাইড না অথবা বিক্রেতা নম্বর লুকিয়েছে**
5. রিকানেক্টের আগে কেন টোকেন আবার পড়ি? → **access token ১৫ মিনিটে বদলে যায়**

## 🔜 পরের ক্লাস (Lesson 8.8)

প্রোফাইল, রিভিউ (বিক্রির পর ক্রেতা রিভিউ দেবে), নোটিফিকেশন, রিপোর্ট আর সেটিংস — অ্যাপের "বিশ্বাস ও নিরাপত্তা" অংশ।
